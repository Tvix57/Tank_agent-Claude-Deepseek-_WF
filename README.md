# WF — папка инструкций ИИ-агентов

Репозиторий хранит правила и раскладку агентов (Claude Code и DeepSeek Harness) **вне контейнера**:
правки не теряются при пересборке контейнера и не расходятся между `.claude` и `.deepseek`.

`main` — только общие, не привязанные к проекту инструкции. Всё, что относится к конкретному проекту
(документация, архитектура, ГДД, агенты, память), живёт в ветке проекта.

## Ветки

| Ветка | Что внутри |
|---|---|
| `main` | общие правила (`CLAUDE.md`), описание механики (этот файл), `tools/link_workspaces.py`, `.gitignore` |
| `my_first_game` | ветка проекта: создана от первоначального коммита, сюда кладутся документы, архитектура и ГДД проекта |
| `tank-docs` | документация и архитектура «Танков»: полное состояние WF-папки на момент разделения веток (агенты, доки, ГДД, память, `.deepseek`) |
| `backup/main-full-state`, тег `backup/pre-restructure` | бэкап состояния до разделения веток |

Правило разделения: общие правила правятся только в `main`, проектные — только в ветке проекта.
Проектные коммиты в `main` не вливать, общие правила в ветку проекта — только осознанным переносом.

## Раскладка ветки проекта

| Папка | Что внутри |
|---|---|
| `Client/` | `CLAUDE.md` — источник правил клиента; `AGENTS.md` и `.deepseek/instructions/project.md` — генерируются конвертером; `.claude/` — команды, скиллы, документация, память; `.deepseek/` — зеркало для dsh |
| `Server/` | то же для сервера (правила и документация сервера отличаются от клиентских) |
| `tools/link_workspaces.py` | пересоздаёт симлинки рабочих каталогов на эту папку |

## Как подключено

- **Контейнер**: `.devcontainer/docker-compose.yml` проекта монтирует эту папку как `/wf`,
  `.devcontainer/devcontainer.json` задаёт `containerEnv: WF_ROOT=/wf`. В рабочих каталогах
  `/workspace/client` и `/workspace/server` `CLAUDE.md`, `AGENTS.md`, `.claude`, `.deepseek` —
  симлинки на подпапки `Client` и `Server` этой папки.
- **macOS (хост)**: `export WF_ROOT="<абсолютный путь к этой папке>"` в `~/.zshrc`. Симлинки ведут на
  `/wf/...`, поэтому на хосте они висят — правки идут через контейнер.

Исключения инструкций из гита рабочих каталогов дописывает `tools/link_workspaces.py` — в локальный
`.git/info/exclude` проекта и только для путей, которые гит пока не игнорирует (проверка через
`git check-ignore`). Отслеживаемый `.gitignore` проекта не трогается: репозиторий проекта не должен
знать про инфраструктуру агентов. Плата за это — exclude не коммитится, поэтому после переклона
рабочего каталога скрипт запускают заново (он же пересоздаёт и симлинки).

## Правка правил

1. Общие, не привязанные к проекту правила — `CLAUDE.md` в `main` (этот репозиторий).
2. Правила конкретного проекта — `Client/CLAUDE.md` / `Server/CLAUDE.md` в ветке проекта.
3. После правки `CLAUDE.md` проекта: `python3 .deepseek/scripts/convert.py export` из рабочего каталога
   проекта — обновляет `AGENTS.md`, `.deepseek/instructions/project.md`, `CLAUDE.ds.md` и зеркало.
4. `python3 .deepseek/scripts/convert.py check` — `changed 0, missing 0`; `python3
   .deepseek/scripts/selftest.py` — инварианты `.deepseek`.

## Если ссылки потерялись (переклонировали рабочие каталоги)

```bash
python3 tools/link_workspaces.py --workdir <папка с client/ и server/>
```

Скрипт идемпотентен: существующие ссылки не трогает, обычные файлы складывает в
`<workdir>/.wf-backup/repo-files-<дата>/` перед заменой, недостающие исключения дописывает в
`.git/info/exclude` проекта.
