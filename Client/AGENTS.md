# AGENTS.md — правила проекта My_first_game (клиент)

Источник: `CLAUDE.md` в этой же папке, копия без изменений по смыслу. Файл должен генерироваться
`.deepseek/scripts/convert.py export`; конвертер в эту ветку ещё не портирован, поэтому копия
поддерживается вручную — править нужно `CLAUDE.md`, сюда переносить вручную и сверять по смыслу.

Общие правила, не привязанные к проекту, — `../CLAUDE.md` (корень WF-папки). Этот файл уточняет их в
своей области и не отменяет молча. Язык общения, обращение «Пользователь»/«ИИ», проверка на
противоречие с ранее принятыми решениями и порядок вопросов — из общего файла.

## Что за проект

- Мобильная игра, **только клиент**: без сервера, аккаунтов, облачных сейвов, PvP, глобальных рейтингов
  и любых механик, требующих валидации на бэкенде.
- Движок: **Cocos Creator 3.8.8**, язык — **TypeScript**.
- Жанр: колония-симулятор в духе Oxygen Not Included, run-based (забег на 10–15 смен), портретная
  ориентация. Референсы: Oxygen Not Included (системы, приоритеты), Frostpunk (тепло, тон),
  Against the Storm (run-структура), Fallout Shelter (мобильный ритм сессии).
- **Источник истины по дизайну — `CONCEPT.md` в рабочем каталоге проекта.** Изменение баланса, систем
  или структуры забега начинается с правки этого файла; код следует за документом. Расхождение кода и
  `CONCEPT.md` — дефект, а не «новая фича».

## Границы, которые нельзя нарушать

1. **Нет серверной логики.** Никаких запросов за игровыми данными, кроме приёмников аналитики и
   рекламных SDK. Всё состояние игры — локально.
2. **Нет монетизации, требующей серверной валидации.** Только реклама (rewarded/interstitial) и IAP
   уровня «убрать рекламу»/косметика. Никаких лутбоксов, гачи, энергии, кулдаунов, продажи преимуществ.
3. **Сейв не защищён от подделки и не должен быть ценным.** Никакой валюты с реальной ценностью,
   сезонных рейтингов, обменов между игроками.
4. **Мультиплеер не планируется** ни в каком виде, даже «асинхронный».

## Архитектурные рамки

1. **`core/` не знает про движок.** Логика симуляции — в модулях без импортов из `cc`: прогоняется в
   Node, тестируется и балансируется без Cocos. Всё про ноды, спрайты, анимации и ввод — в слое `game/`.
2. **Детерминизм обязателен.** Состояние симуляции — целые числа или fixed-point, без `float` в
   сохраняемом состоянии; случайность — только собственный RNG с явным сидом (`runIndex`, `tick`);
   `Math.random()` в логике запрещён.
3. **Симуляция по тикам, а не по кадрам:** базовый шаг 250 мс (4 Гц), ускорение — больше тиков за кадр.
   Падение fps не меняет результат симуляции.
4. **Весь баланс — в данных.** Числа (потребление, тепло, цены, кризисы) в JSON-конфигах и таблицах,
   а не в коде. Схема конфигов версионируется.
5. **Уровни и забеги — процедурные от правил и сида**, а не ручная сборка сцен.

## Бюджеты (проверяются на каждом этапе, а не перед релизом)

| Метрика | Бюджет |
|---|---|
| Размер сборки | < 30 МБ (веб/мини-игра < 10 МБ) |
| ОЗУ | < 250 МБ |
| Комнат на деку | ≤ 40, дупликантов ≤ 8 |
| Draw calls | ≤ 60 |
| fps | 60 на средних устройствах, ≥ 30 на слабых |
| Тик симуляции | ≤ 2 мс обработки на тик |

## Среда работы

- Текущая среда — **Cline (VS Code) на macOS-хосте**, не контейнер Claude Code. Соответствия
  инструментов из общих правил:
  - `AskUserQuestion` → `ask_question` (один вопрос за вызов, независимые вопросы — отдельными вызовами);
  - `Agent tool` / `task` (субагенты) → недоступны: роли выполняются последовательно в одной сессии;
  - `CronCreate`/`CronList` и скрипт контроля токенов → не применимы;
  - `/workspace/client` → рабочий каталог проекта на хосте.
- Правило проверки ветки по `.claude/session_state.json` действует: файл есть, `lastBranch`
  обновляется базовой сессией при смене ветки.

## Пайплайн команд

Пайплайн (библиотекари → аналитики → разработчики, плюс ревью) **подключён**: устройство — в
`.claude/docs/agent-system-workflow.md`, роли — в `.claude/agents/`:

- лиды (общие на весь проект, к фиче не принадлежат): `leads/librarian-lead`, `leads/analyst-lead`,
  `leads/developer-lead`;
- ГДД (отдельная ветка «концепты → ГДД», общая роль): `gdd/gdd-writer`;
- специалисты фичи `room`: `features/room/` — `room-librarian-docs`, `room-librarian-patterns-gamedev`,
  `room-analyst`, `room-analyst-ui`, `room-core-developer`, `room-ui-developer`, `room-fix-reviewer`.

Роль — контракт, а не субагент: файл читается перед исполнением, роли выполняются последовательно в
одной сессии. Вход: `librarian-lead` → `analyst-lead`, если документации нет → `developer-lead` →
`room-fix-reviewer`, если правка меняет границу `core/` ↔ `game/`. Если задача пришла папкой
концептов (новая фича, по которой ГДД ещё нет) — вход другой: `gdd-writer` собирает ГДД из
концептов, делает выжимку по фичам со ссылками на папки изображений и передаёт его `analyst-lead`,
дальше как обычно; в остальных задачах роль не вызывается. Лиды общие: новая фича добавляет папку
`features/<фича>/` со своими специалистами, лиды не пересоздаются. Реестр документации —
`.claude/docs/component-docs-registry.md`, память ролей — `.claude/memory/`, правила записи —
`.claude/docs/agent-memory.md`.

Работать через пайплайн или напрямую — спрашивает Пользователь. Работа над инфраструктурой агентов
(`.claude/*`, этот файл) идёт напрямую, без пайплайна.

## Код

- Без архитектурных эссе в коде; длинные пояснения — в документации проекта, в коде допустима одна
  строка-ссылка на документ.
- Новый файл создаётся в своём слое (`core/` или `game/`), а не «рядом с похожим».
- Сторонние библиотеки не добавляются без явного решения Пользователя.

В рабочем каталоге проекта `CLAUDE.md` и `AGENTS.md` — **симлинки на эти файлы** в WF-папке; копий там
нет, править файлы в рабочем каталоге нельзя. Ссылки внутри инструкций — относительные.
