# Бэклог
Обозначения: **[C]** — правка только в клиенте, **[S]** — правка только на сервере, **[C+S]** — правка нужна на
обеих сторонах или в контракте между ними, **[ГДД]** — сначала нужно решение геймдизайна, **⚑** — приоритет.
Метка показывает, где нужно менять код, а не где проявляется проблема. Внутри раздела задачи сгруппированы по
меткам. Разделы «Документация и ГДД», «Принято „как в коде“» и «Закрыто» меток не имеют: это не правки кода.

Состояние на 2026-10-23. Все задачи отложены владельцем проекта, ни одна не исправлена, если не сказано иное.
Номера строк в путях даны на дату находки и могут сдвинуться, поэтому перед исправлением сверьте их с актуальным
кодом.

## Как читать

У каждой задачи два блока:
- **Проблема** — что не так и где это в коде;
- **Влияние** — что увидит игрок или чем это грозит проекту.

Где лежит код:
- **клиент** (TypeScript + PIXI) — пути от корня репозитория клиента, обычно `src/...`;
- **сервер** (Java + MongoDB) — классы из `game/src/main/java/com/linkedgames/game/...`; путь для краткости опущен,
  класс ищется по имени.

Клиент и сервер общаются по WebSocket. На запрос сервер отвечает `ok` или `error`, а изменения состояния
дополнительно присылает push-сообщениями (сервер шлёт их сам, без запроса клиента).

## Словарь игры

| Термин | Что это |
|---|---|
| ГДД | Документ игрового дизайна: утверждённые правила игры. |
| ТЗ | Техническое задание от геймдизайнера; ГДД составлялся по ТЗ и сверялся с кодом. |
| Сумка | Инвентарь игрока: ресурсы (серебро, золото, схемы, части) и техника (танки, самолёты). |
| Схема танка / самолёта | Ресурс, который тратится на один призыв техники. |
| Поезд | Главный источник танков: за схему выпадает случайный танк, игрок его берёт или продаёт за 10 серебра. Иногда вместо танка выпадает предмет коллекции. |
| Автопризыв | Режим поезда: призыв повторяется без кликов, неподходящие танки продаются автоматически. |
| Ангар | 12 слотов команды танков, разбитых на ряды по типу танка. В бой идут танки из слотов. Новый танк заменяет самый слабый в своём ряду, за заменённый игрок получает 10 серебра. |
| Аэродром | 8 слотов самолётов команды. |
| Военная база | Постройки, штаб с бустерами, склад ресурсов и авиазавод, который производит самолёты. |
| Сборка | Сбор танка из частей: игрок покупает чертежи за серебро и набирает очки до сборки. |
| Кампания | Бесконечная цепочка автоматических боёв против бота. Бой считается на клиенте; если игрок заявил победу, сервер пересчитывает бой по тому же случайному зерну (seed). |
| AirDrop | Самолёт во время боя кампании сбрасывает ящик с золотом, игрок забирает его кликом. |
| Коллекции | Наборы предметов (альбомы, экспериментальные танки) с наградами за сбор. |
| Кодекс | Справочник лучшей техники, которая когда-либо выпадала игроку (вкладка профиля). |
| Квесты | Быстрые задания на главном экране с наградой схемами. |
| Достижения | Долгие задания с рангами и наградами. |
| Туториал | Обучение новичка. Сейчас это два шага в поезде. |
| Удержание (hold) | Клиент временно не показывает в шапке пришедшую награду, пока к шапке летят иконки, а потом снимает удержание. Если удержание не снять, баланс в шапке остаётся заниженным. |
| Слот / position | Номер места в интерфейсе и индекс в коде: у танков слот N = position N−1, у самолётов слот N = position 8−N. |
| Battlefield | PvP-режим в реальном времени (лиги, рейтинг). |
| Merge amnesia/fix | Крупное слияние ветки 2026-10-19. Удалило радиовышку аэродрома, старый туториал и часть механик, добавило военную базу и кланы. |

## 1. Сквозные задачи

**Стык client↔server [C+S]**

- [ ] ⚑ [C+S] **Ошибка сервера без кода выглядит для клиента как успех**
  - **Проблема:** часть роутов отвечает `{ result: "ERROR" }` без `errSection`/`errCode` и без текста. Клиентский
    `WSSocket.sendRequest` при таком ответе успешно резолвит промис, а окна не проверяют результат через
    `ResultUtils.isOk` и сразу читают поля ответа. Известные места:
    - сборка, сервер: `/compare` отвечает пустой ошибкой, если награда не танк; тексты ошибок есть только у
      `/buySchemeParts` (с опечаткой «enougth»);
    - сборка, клиент: после ошибки `/take` или `/reject` состояние окна `AssemblyPopup` становится `undefined`, окно
      падает на `data.reward`, а `ASSEMBLY_UPDATE(undefined)` ломает плашку на главном экране; после `/compare` окно
      сравнения получает пустой танк. Сервер отвечает ошибкой, если частей меньше нужного или награда не танк;
    - поезд, клиент: ошибочный ответ `/accept`/`/refuse` (например, двойной клик) записывает `data.train =
      undefined`, следующая пересборка плашки падает на `this.data.train.receivedTank`;
    - военная база, клиент: `/acceptAirplane`, `/refuseAirplane` (`MilitaryBaseAviationFactoryPopup.ts:342-361`)
      без поля `militaryBase` в ответе дают `setMilitaryBaseData(undefined)`; `/takeProfit`
      (`MilitaryBaseStoragePopup.ts:391+`) на пустом ответе бросает исключение, которое глушит `catch`.
  - **Влияние:** вместо сообщения об ошибке игрок видит сломанное окно или плашку до перезахода (сборка, поезд,
    военная база), автопризыв обрывается, сбор прибыли склада молча не срабатывает. Чинить можно в одном месте
    (`WSSocket` отклоняет промис при `ERROR`, сервер добавляет коды) или в каждом окне; выбор — при задаче.

**Сервер [S]**

- [ ] ⚑ [S] **Античит наград за бой**
  - **Проблема:** роуты наград кампании `/battleTankReward` и `/battleAirplaneReward` (`CampaignPage`) не проверяют,
    что бой идёт и что уничтоженный юнит в нём был (в коде заглушка `if (true) // TODO`). Каждый вызов
    `/battleTankReward` начисляет серебро в пределах лимита и бросает шанс на схему танка. По переданным `tankId`
    и `airplaneId` без проверки растёт прогресс достижений и квестов «уничтожь N». Кроме того, `/battle` отдаёт
    клиенту seed и состав бота до начала боя, и бой можно заранее проиграть у себя, а играть только выигрышные.
  - **Влияние:** запросами в обход клиента можно получать схемы (в среднем около 6 за серию лимита, ни одного боя
    не проводя), накручивать достижения (у самолётов нет даже лимита серебра) и квесты, а также выбирать только
    выигрышные бои. Неизвестный `tankId` вызывает NPE на сервере. Чинить вместе: кампания, достижения, квесты.

- [ ] [S] **Сервер падает на пробелах в таблицах баланса**
  - **Проблема:** данные баланса читаются без проверок:
    - `Balance.getTanks(rank)`/`getAirplanes(rank)` возвращают `null`, если моделей ранга нет, и вызывающие
      (`TrainUserComponent`, `AssemblyUserComponent.generateReward`, `MilitaryBaseAviationFactory.generateAirplane`,
      `CodexPage`, `BattleDataFactory`) это не проверяют;
    - `DropUtils.RollDrop` при нулевой сумме шансов вызывает `nextIntInclusive(1, 0)` →
      `IllegalArgumentException`: так бывает, если в листе `SummonRankChances` нет строки для уровня поезда (листы
      `Summon*` общие с военной базой) или шансы звёзд для уровня в сборке нулевые;
    - одна битая строка любого листа роняет загрузку всего `Balance`.
  - **Влияние:** ошибка в Google-таблице баланса ломает призыв в поезде и на военной базе, генерацию награды сборки,
    кодекс или загрузку сервера целиком. Сейчас данные согласованы, согласованность листов держится вручную.

- [ ] [S] **Доступ к функциям проверяет только клиент**
  - **Проблема:** пороги открытия зашиты в клиенте, сервер их не знает: автопризыв поезда — с 10-го уровня кампании
    (`Vars.AutoSummonAccessLevel`), сборка — при 12 танках (`Vars.AssemblyAccessHangarSize`). Клиент только прячет
    кнопку, а серверные роуты доступны всегда. Порог аэродрома (5-й уровень, `Vars.AerodromeAccessCampaignLevel`)
    после merge не используется ни одним подключённым классом.
  - **Влияние:** изменённый клиент или прямой запрос откроет функции раньше задуманного; баланс прогрессии
    держится на честности клиента.

**Клиент [C]**

- [ ] [C] **Перевести все анимации полёта награды на `RewardFlightUtils`**
  - **Проблема:** в ветке koba/lootbox появился общий `src/plain/RewardFlightUtils.ts`: удержание ресурса в сумке,
    полёт иконок к цели и снятие удержания по окончании полёта. Им пользуются лутбоксы, окно «Трофеи»
    (`IdlePopup`) и квесты (`HomeScreenQuest`). Остальные места до сих пор вручную ставят удержание и запускают
    `FlyIconsAnimation`, каждое по-своему:
    - поезд: `HomeScreen` (`/accept`, `/refuse`), `TrainBuySchemesPopup`;
    - аэродром (`AirplaneGetPopup`);
    - военная база — три окна;
    - достижения (`AchievementLine`);
    - офферы (`GoldenCoinsOfferPopup`);
    - кампания: `CampaignBattleGround`, `AirDrop`.
  - **Влияние:** одна механика повторена примерно в десяти местах. Ошибка в одном из них, например полёт к цели
    без подписчика, оставляет удержание навсегда, и счётчик ресурса занижен до перезагрузки (см. «Удержание схем
    самолёта не снимается» в разделе «Аэродром»: `HomeScreenQuest` и `IdlePopup` в ветке koba/lootbox уже
    переведены, остался `CampaignBattleGround`). Перевод — после слияния koba/lootbox.
  - **API (2026-10-30):** `hold(rewards, owner): number` ставит удержание и привязывает его к `Layout`
    владельца; `fly(id, from)` запускает полёт и снимает удержание по прилёту; `cancel(id)` снимает удержание без
    полёта. Повторный или неизвестный id ничего не делает; при уничтожении владельца без `fly` удержание снимается
    само сразу после обработчиков уничтожения.

- [ ] [C] **`UserBag.releaseHold` не снимает удержание, если push ещё не пришёл — счётчик валюты занижен**
  - **Проблема:** `src/plain/user/UserBag.ts`, `releaseHold(tag)` (`:153-178`). Пометка `applied = true` ставится
    только в `bagUpdate` (`:80`), когда сервер прислал `/events/bag/update`. Если полёт награды закончился раньше
    этого push (частый случай: попап закрыли быстро), `releaseHold` попадает в ветку `if (!applied) continue`
    (`:158-160`) и запись **не удаляет**. На следующем push `applied` станет `true`, владелец уже снял удержание и
    повторно его не снимет — запись висит до перезагрузки, баланс занижен на её величину.
  - **Воспроизведение:** открыть лутбокс с наградой в серебре, закрыть попап награды до прихода push о награде, затем
    ускорить другой сундук за серебро и золото — счётчик серебра уходит в минус или в неверное значение.
  - **Влияние:** счётчик показывают неверное число, игрок уходит в магазин с «не хватает валюты»; затрагивает все
    места с удержанием (поезд, магазин, военная база, кампания, достижения, лутбоксы). Путь через
    `RewardFlightUtils` страдает так же: он снимает удержание через тот же `releaseHold`.
  - **Направление решения (2026-11-04):** в `releaseHold` не пропускать запись с `applied === false`, а удалять её
    сразу: серверное значение ещё не применялось, восстанавливать нечего, а на будущем push удержания уже не будет.
    Клампинг значения в анимации хедера (`HeaderSilverCoinsBar.animationValue`) проблему не решает — он скрывает
    отрицательное отображение, но не утечку записи.
  - **Не сделано:** правка общего механизма `UserBag` вне объёма задачи лутбоксов, отложена решением пользователя
    2026-11-04.
