# Реестр документации компонентов

Владелец — `librarian-lead`: только он правит этот файл. Остальные роли и базовая сессия
читают; изменения передают ему.

Колонки:

- **Компонент** — экран, панель или самостоятельная область симуляции.
- **Путь** — папка или файл от `Last_shift/assets/`.
- **Документация** — путь от `.claude/docs/`; `—` — документа нет.
- **Статус** — `обычный` (по итогам разработки или по прямому запросу Пользователя), `auto-create`
  (по сканированию кода, доверять с осторожностью), `смешанный` (часть разделов auto-create — какие,
  указано в шапке документа), `частично` (что именно покрыто — в скобках), `нет`.
- **Обновлено** — дата последней правки документа или дата внесения строки для `нет`.
- **ГДД** — разделы `CONCEPT.md` и тематический документ `concept-gdd/`.

Паттерны и сквозные механизмы (детерминизм, тики, загрузка конфигов) в реестр не входят — их ведёт
`room-librarian-patterns-gamedev`.

## Как добавлять строку

1. Новый компонент назван в задаче или найден при сканировании — строка добавляется с фактическим
   путём; документа нет — `—` / `нет` / сегодняшняя дата.
2. Документ зарегистрирован — ссылка, статус и дата из истории изменений документа.
3. Названия компонентам даёт базовая сессия по конвенции проекта; переименование строки реестра —
   тоже смена имени компонента, она согласуется с Пользователем.
