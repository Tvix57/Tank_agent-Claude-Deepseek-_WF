# Личная память ролей

Механизма `memory: local` из Claude Code в этой среде нет: память — обычные файлы
`.claude/memory/<роль>.md` в папке инструкций. Файл создаётся при первой записи; читается только
тогда, когда к нему отсылает текущая задача.

Память есть у специалистов: специалисты фичи `room` (`room-librarian-docs`,
`room-librarian-patterns-gamedev`, `room-analyst`, `room-analyst-ui`, `room-core-developer`,
`room-ui-developer`, `room-fix-reviewer`) и общая роль ветки ГДД `gdd-writer`. У лидов
(`librarian-lead`, `analyst-lead`, `developer-lead`) её нет: лиды общие на весь проект и
маршрутизируют, их знания — в ростерах, реестре и workflow-документе.

## Что записывать

Только то, что пригодится этой роли в следующих задачах и чего нет ни в коде, ни в документации
области, ни в `CONCEPT.md`:

- **ловушка** — место, где роль уже ошиблась или долго искала (настоящее расположение файла,
  обманчивое имя, дубль конфига);
- **поправка** — замечание Пользователя к работе именно этой роли, с причиной;
- **короткий путь** — повторяющийся вопрос и где на него ответ (ссылка на раздел документа или
  файл кода, без пересказа).

Знание об области — в документ области через `analyst-lead` и реестр. Правило для всего
проекта — в `CLAUDE.md`. Ход текущей задачи не записывается.

## Лимиты

- Файл памяти — до 20 строк тела, строка — до 120 символов.
- Одна запись — одна тема; ссылка на раздел документа вместо пересказа.
- Достигнут лимит — сначала объединить похожие записи и удалить устаревшие, потом добавлять.

## Когда читать и писать

- Читать — когда задача касается темы записи; целиком файл не открывать без причины.
- Писать — один раз, в конце задачи, перед итоговым ответом. Сначала поиск по своему файлу: запись
  на эту тему уже есть — правится она, а не добавляется новая.
- Нечего записать по разделу «Что записывать» — ничего не писать.
- Запись противоречит документу области — устарела одна из сторон: сообщить в `ОТКРЫТО`, документ
  самому не править.
