Любой файл, который ассистент создаёт/использует для СВОЕЙ работы (а не как часть исходного кода
проекта) — кастомные агенты `.claude/agents/<команда>/*.md`, служебное состояние вроде
`.claude/session_state.json`, `.claude/settings.local.json`, сам `CLAUDE.md` — не должен зависеть от
git-коммитов и обязан переживать пересборку контейнера.

**Why:** пользователь явно напомнил это правило во второй раз (значит, оно уже озвучивалось раньше и
не было зафиксировано в памяти). В репозитории `/workspace/client` уже есть прецедент — `CLAUDE.md`,
`.claude/memory/`, `.claude/settings.local.json` намеренно исключены через `.git/info/exclude` (не
через обычный `.gitignore`, который сам коммитится) — то есть эти файлы принципиально не должны
попадать в git-историю.

Механизм, который реально обеспечивает выживание при пересборке контейнера, найден и это НЕ git:
`/workspace/.devcontainer/docker-compose.yml` монтирует весь проект bind-mount'ом
(`- ..:/workspace:cached`) — `/workspace` физически лежит на хосте, а не в файловой системе
контейнера, поэтому `docker compose build`/пересборка образа его не трогает. Требование "не зависеть
от git" — это отдельная, самостоятельная причина (не тащить локальный тулинг ассистента в общую
git-историю, которую видят остальные разработчики через `git clone`/`pull`), а не техническая
необходимость для выживания при ребилде.

**How to apply:**
- Никогда не предлагать закоммитить файлы из `.claude/*` (кроме исходников самого проекта, если такие
  когда-то появятся вне `.claude/`) или `CLAUDE.md` — это правило само по себе, не связанное с
  вопросом "переживёт ли пересборку".
- При создании НОВЫХ служебных файлов такого рода — сразу добавлять их в `.git/info/exclude` (не в
  `.gitignore`), по образцу уже имеющихся записей.
- Про выживание при пересборке контейнера можно не переспрашивать — пока используется этот
  docker-compose с bind-mount `/workspace`, всё физически на хосте и переживёт любую пересборку
  образа само по себе.
