Каждую функцию с бизнес-смыслом сопоставлять с правилом ГДД, которое она реализует; функции одного смысла под разными именами / тонкие обёртки — находить и сводить к одной (имя — по смыслу ГДД). Новую функцию не вводить, если правило уже выражено существующей. Если имя существующей функции не ассоциируется с новой логикой — не переименовывать молча и не делать обёртку, а спросить пользователя о переименовании, сначала сообщив, где и при каких условиях функция вызывалась раньше и где/при каких условиях будет вызываться в новом решении.

**Why:** 2026-10-05 в коллекциях `isDropEnabled()` (альбомы `= isSectionActive()`, танки `true`) и `isSectionActive()` выражали одно правило «секция активна, пока идёт событие»; аналитики при формировании решения этого не заметили — пользователь указал, что реализация функций не ассоциируется с их назначением по ГДД. `isDropEnabled` убран.
**How to apply:** первоисточник — `agent-system-workflow.md#gdd-function-mapping` (client и server копии) + п.7 стандарта документации; короткие ссылки во всех analyst/developer агентах обоих репо. Применять и в базовой сессии при анализе/правках. См. [[server-collections-fix-decisions-2026-10-05]].
