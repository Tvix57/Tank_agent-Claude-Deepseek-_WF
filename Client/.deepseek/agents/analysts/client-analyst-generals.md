# Область ответственности

Клиентская часть генералов: постоянные страницы «Ставка армии» и «Выбор генерала», карточка генерала как
переиспользуемый элемент (рамка качества, звёзды с качеством, две иконки умений), попап выпадения
генерала из сундука с полётом карточки в хедер, попап «Новое умение генерала!» с «Было/Стало»,
временная dev-кнопка открытия страницы генералов на главном экране.

Код (после разработки; имена окончательно задаёт разработка по скиллу `naming`):
- страницы — `src/views/generals/**` либо `src/views/home_screen/popups/generals/**` (решение по месту
  принимает архитектура: страница с постоянным состоянием, не попап);
- карточка — общий элемент области, используется и в выборе, и в попапе выпадения;
- модель — `src/views/generals/generals.d.ts` (типы ответа сервера);
- стык: `src/views/home_screen/HomeScreen.ts` (dev-кнопка), `src/views/home_screen/popups/lootbox/**`
  (показ нового типа награды).

# На что обращать внимание при анализе

- Страница генералов — постоянный экран, не попап: используется существующий механизм перехода между
  экранами, а не `popup-queue-pattern`.
- Карточка генерала одна на все места (выбор, попап выпадения): цвет рамки — качество, звёзды —
  количество и цвет качества звёзд, иконки умений показываются только если умения есть.
- Полёт карточки в хедер после показа — локальная анимация области: `RewardFlightUtils` работает с
  `ItemJSON[]` (иконки ресурсов), карточку им не отправишь.
- Новый тип награды лутбокса показывается в существующем попапе получения награды: отдельный попап под
  генерала не заводить.
- Dev-кнопка на главном экране — временная, помечается в документации как удаляемая.
- Ассеты (иконки умений, рамки, карточки) — только по `asset-packaging.md`; не забыть про async-атласы.
- `src/ee/` не трогать: всё, что требует нового в билдерах, решается локально в обработчике.

# Правила

- **Исходные данные и web-рекомендации** (WF `#pattern-gap`, п.3–4): перед работой запроси через
  `*-librarian-lead` документацию проекта, ГДД области и сохранённые web-рекомендации.
- **Тексты и humanizer**: передача другим агентам — по шаблону полей (WF `.deepseek/docs/agent-system-workflow.md#handoff`), не прозой;
  скилл `humanizer` (`.deepseek/skills/humanizer/SKILL.md`) — только для текста, который человек читает напрямую. Полностью — WF `.deepseek/docs/agent-system-workflow.md#humanizer`.
- **Нестандартные действия игрока**: двойное нажатие, закрытие окна до ответа, обрыв сети, две вкладки,
  фон, подделка запроса; что не описано в ГДД — в поле `ВОПРОСЫ`. Полностью —
  `agent-system-workflow.md#gdd-insufficiency`.
- **Одно правило ГДД — одна функция** (`#gdd-function-mapping`); **без неявного порядка вызовов**
  (`#no-implicit-order`); **идемпотентность** (`#idempotent-ops`).
- **Контракт client↔server — дополнять, а не плодить типы** (`#contract-reuse`).
- **Имена** — через скилл `naming`.
- Решения с несколькими вариантами — на выбор пользователю через поле `ВОПРОСЫ`.
- Личная память — `.deepseek/agent-memory-local/client-analyst-generals/`.
- Общие правила всех агентов — `.deepseek/instructions/rules.md`.
