## 1. Назначение

Постоянные страницы «Ставка армии» и «Выбор генерала», переиспользуемая карточка генерала, показ генерала и
умения как награды сундука, временная dev-кнопка входа.

<a id="patterns"></a>
## 2. Паттерны и референсы

- `panels-buttons-presets-architecture.md` — карточки, рамки, кнопки.
- `popup-queue-pattern.md` — очередь попапов (оба попапа области идут через неё).

<a id="screens"></a>
## 3. Экраны и переходы

Два постоянных экрана (не попапы); вход — временной dev-кнопкой с главного экрана.

| Экран | Что показывает | Переходы |
|---|---|---|
| «Ставка армии» | дерево должностей: Главком и два заместителя в ряд, ниже Штаб танковых войск на 4 слота; за прокруткой авиационное древо: Командующий ВВС, Первый заместитель ВВС, Начальник Штаба ВВС, Штаб авиационных войск на 5 слотов. У каждой должности — суммарный бонус и её генерал либо пустой слот | нажатие на генерала или пустую должность → «Выбор генерала» этой должности |
| «Выбор генерала» | «назад», заголовок — название должности, сетка карточек по 3 в ряд, внизу полоса из 15 кнопок — по одной на слот | нажатие на карточку — поставить в слот, повторное — снять |

- Скролл на «Ставке» обязателен: всё авиационное древо видно только прокруткой (ГДД `gdd-army-hq`).
- Кнопка должности внизу переключает выбор на неё без возврата на «Ставку».
- Слот не привязан к нации: в выборе — генералы этой должности любой страны; порядок — по убыванию силы,
  при равенстве по имени (ГДД `gdd-slots`, `gdd-selection`).
- Замена ручная: прежний генерал остаётся в инвентаре, автопродажи и общего сравнения между слотами нет
  (ГДД `gdd-slots`).

<a id="card"></a>
## 4. Карточка генерала

Один элемент на все места: выбор, попап выпадения, попап умения.

- Рамка — цвет качества (`rank`); звёзды — количество 1..5 и цвет их качества; имя и фамилия, портрет.
- Прибавки — подписи «% к прочности» и «% к урону» с иконками щита и урона (`armorPercent`, `damagePercent`).
- Иконки умений в правом верхнем углу — только у занятых слотов additional-навыков, у каждой свои звёзды.
  Base-навыки на карточке не показываются: их видно в «Разборе» (ГДД `gdd-abilities`, `gdd-selection`).

<a id="popups"></a>
## 5. Попапы награды

**Генерал из сундука** — показывается в существующем попапе награды лутбокса, отдельный попап не заводится:
карточка появляется по центру, пауза, улетает к хедеру, уменьшаясь, попап гаснет сам.

- Полёт идёт не через `RewardFlightUtils` (тот работает с `ItemJSON[]` и иконками ресурсов): уменьшающаяся
  карточка — локальная анимация этой области в месте показа награды, как у предмета коллекции; снаружи
  `src/ee/` для неё ничего не требуется.

**Новое умение генерала** — отдельный попап области: карточка генерала, поверх неё иконка умения, подписи
«Было +N %, +N %» и «Стало +N %, +N %»; закрытие по фону (ГДД `gdd-ability-drop`). Показывается только при
`applied`; при `sold` попапа нет — сразу анимация продажи, как у коллекций.

**Окно сравнения** — попап области по образцу `TankGetPopup`: две карточки (выпавший и текущий в слоте), у
каждой сила, между ними разница с анимацией «+N / −N», кнопки «В слот» и «Продать» с подсветкой по сравнению
силы. Кнопки swap нет — карточки уже подписаны «выпавший» / «в слоте». Закрытие по фону = ничего не менять
(ГДД `gdd-slots`). Показывается только при занятом слоте: свободный заполняется автоматически, без окна.
Разметка — не копия танка, а `GeneralCard` (§4); тексты кнопок — в i18n области.

<a id="dev"></a>
## 6. Dev-кнопка (временная)

Кнопка на главном экране открывает «Ставку армии». Временная до определения постоянного входа (ГДД `gdd-drop`,
решение Пользователя 2026-11-06); при появлении постоянного входа удаляется.

<a id="assets"></a>
## 7. Ассеты

Рамки 10 качеств и звёзды качества переиспользуются от техники; новые — подложка карточки, портреты
генералов, иконки навыков. Всё строго по `asset-packaging.md`: async-атласы для постраничных иконок (портреты,
навыки), обычные — для статики.

<a id="contract"></a>
## 8. Контракт

Типы — `generals.d.ts` области. Поля ответов (карточка генерала, справочник `/info`, попап умения, награды
сундука) описаны один раз у производителя — server `generals-architecture.md` §7; здесь не дублируются.

- Клиент различает исход по двум флагам: `applied` — выпавшее умение встало (попап «Было/Стало»), `sold` —
  умение продано сразу (`general`, `before`, `soldSkill` = `null`), вместо попапа — анимация продажи.
- `slotGeneral` = `null` — слот был свободен, окно сравнения не нужно; иначе окно показывает силу обоих.
- Ответ сервера расширяет существующие типы: `GENERAL` в `ItemType`-ответе, справочник должностей и данные
  генерала — один набор типов на страницу и попапы, отдельные типы под каждое окно не заводятся
  (`#contract-reuse`).
- Названия навыка в балансе нет: подпись на клиенте собирается из типа влияния и `value`.

<a id="open"></a>
## 9. Открытые вопросы

- Постоянный вход на страницу генералов не определён — пока dev-кнопка.
- Числа прибавок на карточке и правила их подсветки, иконки под 22 типа влияния — после баланса.
- Кнопка «Продать» в попапе умения (ГДД `gdd-ability-drop`): сервер уже применил умение, поэтому действия для
  продажи на клиенте пока нет — нужно убирать умение с генерала и начислять серебро.
