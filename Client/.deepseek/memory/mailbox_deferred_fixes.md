Доки: client `mailbox-architecture.md#tradeoffs`, server `/workspace/server/.claude/docs/mailbox-architecture.md#tradeoffs`;
ГДД `game-design/mailbox-gdd.md` — черновик по коду. Почта в коде = личная переписка + друзья + ЧС; наград из писем
и рассылок нет (заглушки, О1 — ждём ТЗ). Пользователь 2026-10-17 подтвердил одно правило (системные письма доходят
до игрока); все остальные правила кода и непрочитанное — в #gdd-open О2–О12, задать при следующей задаче по почте.
Ничего не чинили. Главное:
- кросс-репо, приоритет: письмо о бане теряется (server `receiveSystemMessage` — TODO) + на клиенте нет декодера
  системных писем (префикс `|s|`) — нарушает подтверждённое правило;
- сервер: `MailboxUserComponent.init()` нигде не вызывается → после входа непрочитанное пусто, старые диалоги не
  помечаются прочитанными в БД; `MailboxDao:215` ставит unread=1 вместо +1; delete из друзей/ЧС без onFail;
  отправка несуществующему игроку и добавление себя в друзья/ЧС; 4 независимые записи в БД при отправке;
- клиент: флаг blacklisted не сбрасывается после «в друзья»; поле ввода после конца мута у незарегистрированного,
  тикеры мута копятся; второе окно почты снимает подписку первого (не проверено); ошибки действий не показываются;
  о ЧС у собеседника игрок узнаёт только при отправке (контракт → integration-lead).

Вместе с О2–О12 задать (от server-analyst-mailbox, 2026-10-17): О2 — копить число непрочитанных или только факт
(сервер хранит 0/1, отдаёт unreadDialogsCount числом); «свой ЧС не мешает писать» — правило или упущение (в О7 или
отдельно); добавить ли в #gdd-open «диалоги с собеседником из своего ЧС скрыты в списке и счётчике»; О10 — при
отказе сервер шлёт error, а ГДД пишет «ответа нет»: что видит игрок.

**Why:** документация делалась без задачи на исправление.
**How to apply:** при задаче по почте сначала задать открытые вопросы ГДД О2–О12, затем предложить начать с письма
о бане и init() на сервере. Перед исправлением сверить с актуальным кодом.
