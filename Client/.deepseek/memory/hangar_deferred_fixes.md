Доки: client `hangar-architecture.md#tradeoffs`, server `/workspace/server/.claude/docs/hangar-architecture.md#tradeoffs`;
ГДД `game-design/hangar-gdd.md` (общие правила постановки танка перенесены сюда из ГДД поезда, сборки, кампании,
коллекций 2026-10-17). Ничего не чинили. Главное:
- сервер, высокий: `uid` слота не найден в сумке → новый танк уходит в position 0, прежний остаётся «сиротой».
  Решение пользователя 2026-10-17: такой слот считать свободным (без 10 серебра) + разовый скрипт чистки сирот в
  сумке (аналог CleanupAerodrome) вместе с исправлением. Копии в HangarUserComponent и AerodromeUserComponent НЕ
  объединять, чинить в обеих (см. [[aerodrome-deferred-fixes]]);
- сервер: NPE после удаления заменяемого, если `BagUserComponent.add` откажет; сборка не платит 10 серебра за
  заменённый (server assembly п.14); танк-награда через `User.addItem` минует ангар (открытый вопрос ГДД);
- клиент, высокий: обновление ангара держится на ручном `emit(HANGAR_UPDATE)` у каждого источника — предложение
  push с сервера (контракт → integration-lead); клик по танку, которого нет в сумке → `TankInfoPopup(null)` падает;
- клиент, средний: `onHangarUpdate` без обработки ошибок; карточка слота нарисована тремя способами (эталон
  `HomeScreen.UITank`); раскладка по порядку массива, а не по `position`.
Решено как в коде: лёгкие и ПТ в одном ряду вытесняют друг друга; подпись в окне сравнения привязана к месту;
прочность при замене в бою — текущая заменённого, не выше максимума нового. Термин: «слот» — канон ГДД,
танки слот N = position N−1, самолёты слот N = position 8−N (глоссарий).

**Why:** документация делалась без задачи на исправление.
**How to apply:** при задаче по ангару/источникам танков напомнить; начать с серверного слота-«сироты» и падения
окна информации. Перед исправлением сверить с актуальным кодом.
