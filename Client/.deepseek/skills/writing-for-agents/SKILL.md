# Тексты для агентов

Скилл, `CLAUDE.md`, файл агента, документ по ссылке и строка `MEMORY.md` устроены одинаково: агент
читает их и каждый раз должен проходить один и тот же *путь*. Цель текста — предсказуемое
поведение, а не красивое изложение. Основа — `mattpocock/skills` (writing-for-agents), адаптировано
под инфраструктуру этого проекта.

## Указатели

**Указатель** — то, что постоянно лежит в контексте и называет материал вне его, вместе с условием,
когда за ним идти: `description` скилла или агента, строка в `CLAUDE.md` "читай X, когда Y",
строка в `MEMORY.md`. Сработает ли материал, решает *формулировка указателя*, а не сам материал.
Важный документ за слабым указателем — источник случайного поведения: сначала усилить формулировку,
и только если не помогло — переносить материал в постоянный контекст.

Указатель делает две работы: говорит, что за ним, и перечисляет **ветки** — разные случаи, в которых
за ним надо идти.

- **Ключевое слово — первым**: с него указатель и срабатывает.
- **Один триггер на ветку.** Синонимы одной ветки — это одна ветка, записанная дважды: оставить одну.
- **Не повторять то, что уже есть в теле.**

В проекте это прежде всего `description` агентов (по нему основной агент выбирает, кого звать) и
строки `MEMORY.md` (индекс загружается в каждую сессию целиком).

## Две нагрузки

- **Нагрузка на контекст** — всё постоянно загруженное: `CLAUDE.md`, `MEMORY.md`, `description` всех
  скиллов и агентов. Платится токенами и вниманием на каждом ходу, сработало или нет. В проекте
  это ещё и прямые деньги: почасовая проверка `token_usage_check.py` следит за расходом.
- **Нагрузка на человека** — помнить, какие документы есть и когда за каким идти. Это цена контроля
  пользователя; тратить её там, где нужно его решение, и снимать там, где не нужно.

Материал за указателем не грузит контекст, кроме строки самого указателя. Материал без указателя
целиком держится на памяти человека.

## Иерархия информации

Документ состоит из **шагов** (что делать, по порядку) и **справки** (правила, факты, определения
по запросу). Каждый кусок стоит на одной ступени:

1. **Шаг в файле** — основное: что агент делает.
2. **Справка в файле** — по запросу. Плоский список равноправных правил — нормально.
3. **Вынесенная справка** — в отдельном файле за указателем, читается только когда указатель
   сработал (как `asset-packaging.md` или `agent-system-workflow.md` за строкой в `CLAUDE.md`).

**Постепенное раскрытие** — спуск материала вниз по лестнице за указатель, чтобы верх оставался
читаемым. Тест: что нужно *каждой* ветке — оставить в файле; что нужно *некоторым* — вынести.
Справка, которую стоило вынести, хоронит шаги рядом с ней: внимание к шагам становится лотереей.

**Рядом** держать всё про одно понятие: определение, правила, исключения — под одним заголовком,
а не по разным местам.

**Разрастание** — документ слишком длинный, даже если каждая строка живая и уникальная. Лечится той
же лестницей: вынести справку за указатели, разбить по веткам или по последовательности.

## Шаги и критерий завершения

Каждый шаг заканчивается **критерием завершения** — условием, по которому агент понимает, что шаг
сделан.

- **Ясность.** Размытый критерий ("достигнуто понимание") ведёт к **преждевременному завершению**:
  агент тянется к видимым следующим шагам. Сначала заострить критерий; только если он неизбежно
  размыт *и* спешка реально наблюдается — спрятать следующие шаги, разбив последовательность.
  Прятать работает только через границу контекста (передача другому агенту через `Agent`), не
  внутри одного файла.
- **Требовательность.** "Учтена каждая изменённая модель" заставляет копать, "составить список
  изменений" — нет. Сильный критерий одновременно проверяемый и исчерпывающий.

В проекте так устроены, например, проверки ГДД ("пока внутри ГДД есть несогласованные противоречия,
сверку с кодом не начинать") и поля передачи `СДЕЛАНО / ФАЙЛЫ / РЕШЕНИЯ / ОТКРЫТО`.

## Ключевые слова

**Ключевое слово** — короткое понятие, которое модель уже знает (*костыль*, *первоисточник*,
*точечно*, *auto-create*) и через которое агент думает, пока выполняет документ. Повторяется как
слово, а не как фраза, и якорит целую область поведения минимумом токенов. Придуманное слово тоже
работает, но его надо определять — сначала искать существующее.

Работает дважды: в теле (агент каждый раз делает одно и то же при встрече слова) и в указателе
(если одно слово живёт в промптах, документах и коде, агент надёжнее связывает его с материалом).

Искать места, которые просятся в одно слово: тройка признаков, расписанная в трёх местах; фраза в
указателе, которая жестами описывает одну идею.

**Запрет — слабый рычаг.** "Не делай X" вносит X в контекст и делает его доступнее. Писать
целевое поведение ("пояснение пиши в `.deepseek/docs/<тема>.md`, в коде оставь одну строку"). Запрет уместен
только как жёсткое ограждение, которое нельзя сформулировать позитивно (как `src/ee/` в `CLAUDE.md`),
и даже тогда — в паре с тем, что делать вместо.

## Чистка

- **Один источник истины.** Каждый смысл — в одном месте, изменение поведения — правка одного
  места. Дубль стоит обслуживания, токенов и раздувает вес смысла. В проекте: `CLAUDE.md` даёт
  указатель на `asset-packaging.md` и `agent-system-workflow.md`, а не пересказывает их.
- **Окружение — тоже источник истины** (`package.json`, `pom.xml`, структура папок, сам код).
  Документ, повторяющий его, — **кэш**: оправдан, только если найти самому дорого. Записывать то,
  чего не найти глазами: неписаную договорённость, причину выбора, подводный камень.
- **Актуальность** каждой строки: относится ли она ещё к делу? Иначе копится **осадок** —
  устаревшие слои, потому что добавлять кажется безопасным, а удалять рискованным.
- **Пустые инструкции** — то, что модель делает и так ("будь внимателен"). Тест: меняет ли
  предложение поведение по сравнению с умолчанием? Нет — удалить всё предложение, а не ужать.
  Слишком слабое ключевое слово тоже пустое: лечится более сильным словом, а не другим приёмом.

## Когда разбивать документ

Разбиение тратит одну из нагрузок, поэтому только когда окупается:

- **По последовательности** — если видимые следующие шаги заставляют спешить с текущим.
- **По вызову** (скиллы, см. ниже) — когда у части есть своё ключевое слово-триггер или её должен
  вызывать другой скилл.

## Скиллы: как вызываются

- **Вызываемый моделью** — с `description`, агент запускает его сам, другие скиллы могут его
  вызвать, пользователь тоже может по имени. Цена — описание всегда в контексте. `description`
  пишется для модели, с ветками-триггерами (правила указателей выше).
- **Вызываемый только пользователем** — `disable-model-invocation: true`. Ноль нагрузки на контекст,
  но пользователь должен помнить, что скилл есть; `description` — одна строка для человека.

Модельный вызов — только если агент должен находить скилл сам или его зовёт другой скилл. Общую
справку для двух пользовательских скиллов держать в обычном файле вне скиллов.
Пользовательских скиллов стало больше, чем помнится, — завести **скилл-маршрутизатор**: один
пользовательский скилл, который перечисляет остальные и когда за каким идти.

## Правила проекта для этих файлов

- **Язык — русский** во всех текстах для агентов и в их ответах (правило из `CLAUDE.md`).
- **Новые служебные файлы — вне git**: `.deepseek/skills/`, `.deepseek/agents/`, `.deepseek/docs/`,
  `CLAUDE.md` уже в `.git/info/exclude` обоих репозиториев; новый путь вне этих папок — сразу
  добавить туда же.
- **Общий для client и server скилл** — одна копия в client, в server симлинк
  (`.deepseek/skills/<имя>` → client), правка только в client.
- **Агенты** — frontmatter `name`, `description`, `tools`, `model`; модель — по решению из памяти
  `project_agent_model_assignment.md`. `description` агента — указатель: область, когда звать,
  через кого.
- **Строка `MEMORY.md`** — одна строка на документ, пометка области в `[…]`, хук — только то, что
  нужно, чтобы решить "открывать или нет"; подробности — в самом файле.
- **Якоря `{#...}`** — стабильные: на них ссылаются другие документы; при переименовании `grep` по
  обоим репозиториям и обновить ссылки.
- Работа над `.deepseek/*` и `CLAUDE.md` — напрямую, без пайплайна команд.

## Проверка перед сохранением

1. Каждый указатель (`description`, строка `CLAUDE.md`/`MEMORY.md`) начинается с ключевого слова и
   перечисляет ветки по одному триггеру.
2. В файле — то, что нужно каждой ветке; остальное — за указателем.
3. Каждый смысл — в одном месте; пересказ другого документа заменён ссылкой.
4. Нет предложений, которые не меняют поведение модели.
5. Запреты — только как ограждения и в паре с целевым поведением.
6. У каждого шага — проверяемый критерий завершения.
