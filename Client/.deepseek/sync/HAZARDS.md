# HAZARDS.md — что в DeepSeek иначе и что из этого необратимо

Каждая строка — место, где поведение dsh расходится с Claude Code, и что делать. Перед первой рабочей
сессией в DeepSeek прочитать целиком.

## Необратимые и опасные

| Риск | Что может случиться | Защита |
|---|---|---|
| `export --force` перезаписывает снимок | правки, сделанные руками в `.deepseek/docs|memory|agents`, теряются безвозвратно | перед любым `export` — `git status -s .deepseek`; правки DeepSeek сначала `import` или коммит ветки |
| Снимок не в git | `.deepseek/` и `AGENTS.md` в `.git/info/exclude`: `git clean -xfd`, переезд на другую машину или чужой клон уничтожат его | держать снимок в этом рабочем каталоге; после переезда — `export --force` из свежего `.claude`; если нужна переносимость, коммитить контур осознанно |
| dsh пишет вне рабочей папки | `bash` в dsh видит весь `/workspace`; команда из подкаталога может задеть другой репозиторий | работать из корня репозитория; пути в задачах субагентам — абсолютные |
| Автокоммиты и git-операции dsh | `git reset`, `checkout --force`, перезапись ветки — необратимо | манифест рабочей папки, ветка `-deepseek` (`.deepseek/sync/POLICY.md`), никаких `--force` без вопроса пользователю |
| Ошибка в `import` | `.claude/memory/*` и `.claude/docs/*` перезаписаны версией DeepSeek | `import` без `--force` не перезаписывает расхождения; откат `git checkout -- .claude` |
| Секреты | dsh отправляет содержимое файлов провайдеру модели; `.env`, ключи, токены, дампы БД | не открывать и не просить модель читать секреты; работа с ними — вне DeepSeek |
| Персональные данные | логи игроков, дампы, переписка | то же: не подключать к сессии каталоги с персональными данными |

## Иначе, чем в Claude Code

| Тема | Claude Code | dsh | Что делать |
|---|---|---|---|
| Инструкции подкаталога | `CLAUDE.md` в подкаталоге; `.claude/*` подхватывается | `AGENTS.md` в корне; подкаталоги читаются не всегда | `.deepseek/CLAUDE.ds.md` и `.deepseek/instructions/` читать явно (checkpoint) |
| Субагенты | `Agent` tool, `subagent_type` | `task`, тип = имя агента | вызывать по файлу `.deepseek/agents/...`, инструменты агента — из `traits`; `subagent_type` и `run_in_background` в dsh нет — фоновый запуск не заменяет ожидание результата |
| Контекст субагента | `CLAUDE.md` + `.claude/` подхватываются | инструкции проекта в контекст субагента не попадают | каждая задача — по шаблону `.deepseek/instructions/rules.md#subagents`: файл агента, якорь WF полным путём, «ответ по-русски», `ВОПРОСЫ` полем, синхронный вызов |
| Скиллы | `Skill` tool | плагин skill | читать `SKILL.md` через `read` перед работой |
| Память | `memory: local`, авто-индекс | нет автоматического индекса | `MEMORY.md` читать самому в начале вызова, как в `.claude/docs/agent-memory.md` |
| Хуки | `settings.local.json` | `.deepseek/hooks.json`, поддержка плагином | считать, что напоминаний нет; чек-лист в `.deepseek/instructions/checkpoint.md` |
| Планировщик | `CronCreate` (живёт в сессии) | `schedule` | при сомнении — ручной запуск `token_usage_check_dsh.py` (runtime.md#tokens) |
| Контроль токенов | `CronCreate` + `.claude/scripts/token_usage_check.py` (читает `~/.claude/projects/`) | `token_usage_check_dsh.py` (читает журнал dsh) | пороги те же, но нужен `--sessions-root`; zstd-журнал требует модуля `zstandard` |
| Модели | opus/sonnet/haiku | `deepseek-v4-pro`/`deepseek-flash` | таблица `.deepseek/instructions/bridge.md#модели` |
| Контекст | `/compact`, PreCompact-хук | автоматическое `compaction` | фиксировать состояние в `.deepseek/memory/` и `.deepseek/docs/` до и после сжатия |
| Безопасность правок | `PreToolUse`-хуки, разрешения | политика подтверждений | подтверждения не обходить; запреты из `AGENTS.md` действуют |
| Зависимости | ставит Claude Code по согласованию | может поставить `npm install`/`mvn` сам | сборка — только командами проекта (`npm run build`, `server/scripts/build.sh`) |

## Что DeepSeek умеет делать, а Claude Code в этом проекте — нет

- Редактировать файлы вне репозитория (если разрешено политикой dsh). В проекте это запрещено: работать
  только в репозитории и в `.deepseek`.
- Запускать длинные фоновые задачи (`jobs`) и планировщик. Разрешено, но результат фоновой задачи не
  заменяет проверенный результат субагента.
- Ставить зависимости и менять lock-файлы. В проекте — только по явному решению пользователя и
  стандартной командой сборки.

## Проверки перед каждой сессией DeepSeek

1. `git status -s` — незакоммиченное либо закоммичено, либо осознанно оставлено.
2. `convert.py check` — нет `missing`.
3. Ветка содержит суффикс `-deepseek` (режим B/C).
4. `.deepseek/sync/STATE.md` — последняя строка про актуальную сессию, если их было несколько.
