# Правила сессии DeepSeek

Действуют для базовой сессии dsh и для КАЖДОГО субагента, которого она запускает. Правила проекта из
`AGENTS.md` (копия `CLAUDE.md`) действуют одновременно — этот файл их не отменяет, а переводит в
термины DeepSeek и добавляет то, чего в `CLAUDE.md` нет.

## Жёсткие правила проекта

Текст правил — в `.deepseek/instructions/project.md` (генерируется из `CLAUDE.md`), здесь только то, что в DeepSeek добавляется
к ним. Пересказывать эти правила субагенту в задаче не нужно — передаётся ссылка:

- **Язык.** Требование «ответ по-русски» писать в задаче явно: `AGENTS.md` и `.deepseek/instructions/` в
  контекст субагента dsh не попадают (`.deepseek/instructions/project.md`, раздел «Язык общения»; форма задачи — `#subagents`).
- **Решение выбирает Пользователь.** Варианты с рекомендацией субагент отдаёт вызывающему полем
  `ВОПРОСЫ`, базовая сессия задаёт их одним итоговым вопросом по
  `.deepseek/docs/agent-system-workflow.md#question-order` (`.deepseek/instructions/project.md`, раздел «Порядок вопросов пользователю»).
- **Порог пайплайна** — `.deepseek/instructions/project.md`, раздел «Когда вообще входить в пайплайн команд»: в DeepSeek он тот
  же, своих порогов и скриптов не добавляется.

## DeepSeek-специфика

### Субагенты {#subagents}

- Запуск — через `task` (`@deepseek-ai/dsh-subagent`). Тип агента — имя файла из `.deepseek/agents/`,
  для разовых исследований — встроенные `explore`, `plan`, `general-purpose`, `worker`.
- В постановке задачи всегда указывать: файл агента (`.deepseek/agents/<группа>/<имя>.md`), раздел
  `AGENTS.md`, который нужен, и требование отвечать по-русски.
- **Каждый субагент получает обязательную часть задачи** (шаблон ниже). `.deepseek/instructions/`,
  `.deepseek/docs/` и `.deepseek/skills/` в контекст субагента dsh не попадают: если не написать
  правила в задаче, у него их нет. Минимум, который переносится в каждую задачу:
  1. файл агента и группа (`.deepseek/agents/<группа>/<имя>.md`);
  2. нужные разделы `AGENTS.md` и `.deepseek/docs/agent-system-workflow.md` — полным путём с якорем;
  3. **ответ пользователю только на русском**;
  4. инструкции и скиллы читаются с диска (`read`), а не берутся по памяти;
  5. `ВОПРОСЫ` возвращаются вызывающему полем, а не решаются самостоятельно; зависимые вопросы —
     отдельным вызовом после ответа;
  6. синхронный вызов: результат нужен до следующего шага, ждать его, а не запускать в фоне;
  7. личная память — `.deepseek/agent-memory-local/<имя агента>/MEMORY.md`, читать в начале вызова;
  8. писать только в своём репозитории и только в `.deepseek/docs/`; `.claude/` не трогать.
- **Шаблон постановки задачи** — поля, не проза:

  ```
  АГЕНТ: .deepseek/agents/<группа>/<имя>.md
  ЗАДАЧА: <что сделать, одним абзацем>
  ОБЛАСТЬ: <client | server | обе>
  ВХОД: <файлы, разделы, якоря — что открыть перед работой>
  ВЕРНУТЬ: <какие поля и какой формы ждёт вызывающий>
  ОБЯЗАТЕЛЬНО: ответ по-русски; решения — полем ВОПРОСЫ; синхронный вызов, результат до следующего шага
  ```

  Полные тексты правил (`AGENTS.md`, `.deepseek/docs/agent-system-workflow.md#handoff`,
  `#ask-relay`) субагенту не пересказываются — передаётся ссылка на якорь с путём файла.
- **Синхронность важнее параллельности там, где зависит порядок.** Библиотекари — синхронно и
  параллельно между собой; аналитик и разработчик ждут их результата. Не запускать агента, которому нужен
  результат ещё не завершившегося агента.
- **Лимит одновременных субагентов — 20.** Больше — волнами, библиотекаря синхронно (как в `.claude`).
- Субагент не возвращает результат — не дублировать работу сразу: дождаться, взять выданный результат,
  и только при сбое повторить новым вызовом, сообщив пользователю.
- Фоновые задачи (`jobs`) не заменяют синхронный вызов, когда ответ нужен прямо сейчас.
- **Роль файла агента не смешивается:** лид маршрутизирует, специалист работает. Если задача требует
  правок в двух областях — два специалиста, а не один «универсальный».

### Скиллы

- Скилл вызывается чтением `.deepseek/skills/<имя>/SKILL.md` (для ЧЕЛОВЕЧЕСКОГО текста — `humanizer`,
  для имён — `naming`, для терминов — `glossary`, для передачи агенту — `writing-for-agents`).
- `humanizer` — один вызов в конце задачи на весь текст для человека: коммит, PR, разделы документации,
  длинные вопросы. Не применять к коду, путям, идентификаторам и к передачам между агентами.
- Скилл читается перед работой, а не «по памяти»: правила в нём обновляются, пересказ по памяти
  расходится с текстом.

### Память

Лимиты, форматы и правила записи — `.deepseek/instructions/contracts.md#memory`; здесь только адрес для задачи субагенту:
`.deepseek/agent-memory-local/<имя агента>/MEMORY.md`, читается в начале вызова (`#subagents`, п. 7).
Лидам память не нужна — у них `memory=local` не включён.

### Контроль расхода токенов

Полностью — `.deepseek/instructions/runtime.md#tokens` (свой источник, скрипт, периодичность вместо `CronCreate`); само правило
и разбор ответа — `.deepseek/instructions/project.md`, раздел «Контроль расхода токенов». Здесь не повторяются.

### Инструменты и разрешения

- Инструменты агента — поле `tools` в его traits (`.deepseek/agents/*`). Нет `bash` — агент не запускает
  команды; нет `task` — не запускает субагентов.
- `bash` и правки файлов вне рабочей папки требуют подтверждения по политике dsh — это нормально, не
  считать за ошибку и не обходить через `python -c`.
- `web_search`/`web_fetch` — только у тех ролей, у кого они есть в traits (`web-librarian`, аналитики и
  разработчики платформы, разработчики с веб-поиском).

### Что делать нельзя

Запреты проекта — `.deepseek/instructions/project.md`: «Движковый код в `src/ee/`» и «Никаких кастов к приватным полям» (в
клиенте), «Без рефлексии» (в сервере), «Без развёрнутых комментариев в коде» (в обоих). В DeepSeek они
действуют без изменений, в задаче субагенту — ссылкой, не пересказом. Дополнительно в DeepSeek:

- Не менять `.claude/` во время DeepSeek-режима. Исключение — `import` (слияние документации и памяти),
  и он делается конвертером, а не руками.
- **Конвертер — только по запросу Пользователя.** `export`, `import`, `sync-agents` и другие команды
  `convert.py` не запускаются самостоятельно, в том числе «чтобы проверить» или «чтобы не потерять
  правку». Агент сообщает Пользователю, какая команда нужна и зачем, и ждёт разрешения — как на любое
  действие, меняющее файлы обеих раскладок. Пробный прогон без записи (`check`, `drift`, `status`,
  `sync-agents` без `--apply`) тоже выполняется по запросу Пользователя.
- Не запускать конвертер без `git status` в чистом виде: `export --force` перезаписывает снимок.
- Не менять `AGENTS.md` руками: он сгенерирован; правки — в `.deepseek/instructions/` или в `CLAUDE.md`
  (второе — только когда Claude Code вернётся).
