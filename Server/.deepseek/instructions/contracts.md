# Контракты DeepSeek: память, документация, субагенты, скиллы

То, чего нет в `AGENTS.md` (он дословно повторяет `CLAUDE.md`), но что должно соблюдаться в DeepSeek,
чтобы результат принимался обратно без ручной чистки. Термины — как в `.deepseek/docs/agent-system-workflow.md`.

## Память {#memory}

Три уровня, как в Claude Code:

| Уровень | Где | Кто читает | Лимит |
|---|---|---|---|
| Личная память специалиста | `.deepseek/agent-memory-local/<имя агента>/MEMORY.md` + файлы рядом | этот агент при каждом вызове | индекс 20 строк по 120 символов, файл 20 строк тела |
| Общая память проекта | `.deepseek/memory/<тема>.md` + `.deepseek/memory/MEMORY.md` | все агенты и базовая сессия | 115 строк индекса, как в `.claude` |
| Указатель для человека | `.deepseek/memory/INDEX.md` | человек | без лимита |

Правила записи (что писать, лимиты, когда писать, противоречие с документом области) —
`.deepseek/docs/agent-memory.md`; перенос в `.claude` делает `import`, руками ничего не копировать. Специфика
`.deepseek` — только формат общего файла: YAML-заголовок (`name`, `type`, `title`, `source`) и тело,
`name` равен имени файла (по нему конвертер понимает, что обратный импорт не должен пересобирать файл).

## Документация {#docs}

- Стандарт документа компонента — `.deepseek/docs/agent-system-workflow.md#doc-standard`, плюс
  «Масштабирование глубины» и «Самопроверка перед отправкой». Он не меняется: это тот же текст.
- Регистрация — через `*-librarian-lead`: реестр `.deepseek/docs/component-docs-registry.md`, покрытие
  `.deepseek/docs/source-scan-coverage.md`, скрипт `python3 .deepseek/scripts/scan_coverage.py`.
- **Куда писать.** Только `.deepseek/docs/`. Зеркало `.claude/docs/` не трогается (это источник истины и
  слияние идёт отдельным шагом).
- **Что якорь к ГДД не сломается.** В `.claude` ссылка на правило ГДД пишется `#gdd-...`, в `.deepseek` —
  `gdd-...` (заголовки ГДД содержат `{#gdd-...}`, из которого GitHub-якорь не строится). Ссылаться на
  правила ГДД только в этой форме; конвертер переводит обе формы автоматически.
- Документ, начатый в `.deepseek` и не завершённый, при `import` переносится как есть (текст общий) —
  незавершённость видна по дате в истории документа.
- Архитектурные ссылки из кода (`// См. .claude/docs/...`), которые пишут разработчики в DeepSeek-режиме,
  после `import` не меняются — конвертер их не трогает: код ведёт отдельная ветка (`.deepseek/sync/MIGRATION.md#c-merge`).

## Субагенты {#subagents}

- Каталог агентов — `.deepseek/agents/<группа>/<имя>.md`, группы те же: `librarians/`, `analysts/`,
  `developers/`, `integration/`.
- Frontmatter DeepSeek-агента: `name`, `description`, `traits` (список: модель, `tools=`, `memory=local`).
  Соответствие с `.claude` — `.deepseek/sync/CONVERSION.md#agents`.
- **Новый агент.** Файл агента в DeepSeek-формате — это `.deepseek/agents/<группа>/<имя>.md` с `traits`, а не
  YAML `.claude`. Порядок:
  1. `.deepseek/agents/<группа>/<имя>.md` создаётся по образцу соседних: `name`, `description`, `traits`
     (модель, `tools=`, `memory=local`). Шаблон — `.deepseek/agents/_TEMPLATE.md`.
  2. `python3 .deepseek/scripts/convert.py import` — файл попадает в `.claude/agents/<группа>/<имя>.md`
     уже в формате Claude Code (`tools` из `tools=`, модель `pro`->`opus` / `flash`->`sonnet`).
  3. Ростер команды в файле лида и запись в `.deepseek/sync/STATE.md` («новый агент <имя>») — строкой,
     чтобы при возврате в Claude Code правка не потерялась между слияниями.
- Новые строки ростера, добавленные в DeepSeek-копии лида, обратно в `.claude` автоматически не
  переносятся: `import` не перезаписывает существующих агентов. Дублируйте такие правки строкой в
  `.deepseek/sync/STATE.md`.
