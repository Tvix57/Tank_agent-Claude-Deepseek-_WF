# POLICY.md — что источник истины и чего нельзя

Политика контура `.deepseek`. Действует в обоих режимах (Claude Code работает или нет).

## Источник истины

- **`.claude` — основная раскладка.** `CLAUDE.md`, `.claude/docs/`, `.claude/memory/`, `.claude/agents/`,
  `.claude/skills/` правятся в Claude Code и оттуда попадают в `.deepseek` через `export`.
- **`.deepseek` — снимок плюс дельта.** Снимок всегда повторяет `.claude`; дельта — то, что родилось в
  DeepSeek и ещё не перенесено обратно (`import`).
- **`AGENTS.md` — производное от `CLAUDE.md`.** Правка в `AGENTS.md` живёт до следующего `export`.
- **Правила проекта** (`CLAUDE.md` -> `AGENTS.md`) — исключение из «`.claude` всегда первым»: если Claude Code
  недоступен, правило пишется в `.deepseek/instructions/` и переносится в `CLAUDE.md` при возврате
  (`.deepseek/sync/MIGRATION.md#b-back`). Но пока Claude Code доступен — только `CLAUDE.md`.

## Границы правок

| Что | В режиме A (Claude Code работает) | В режиме B/C (DeepSeek) |
|---|---|---|
| `src/`, `game/` (код) | как обычно | только в режиме C, в отдельной ветке |
| `CLAUDE.md` | да | нет |
| `.claude/**` | да | нет (кроме `import`) |
| `.deepseek/{instructions,sync,README}` | руками, редко | да |
| `.deepseek/{docs,memory,agents}` | руками нельзя: `export` перезапишет | да, это рабочая копия |
| `.deepseek/{AGENTS.md? нет, CLAUDE.ds.md}` | нет | нет |
| `AGENTS.md` (корень) | нет (генерируется) | нет |

## Ветки

- Режим A — рабочая ветка как есть.
- Режимы B/C — копия рабочей ветки с суффиксом `-deepseek`. Причина: в DeepSeek-режиме меняются
  `.deepseek`, а иногда и код; основная ветка должна оставаться в состоянии, которое собирается и
  открывается в Claude Code.
- DeepSeek-сессий с разными задачами — разные ветки, как и в Claude Code. Слияние — только через
  `.deepseek/sync/MIGRATION.md#c-merge`.

## Конфликты {. #конфликты}

`check` показывает `changed` для файла, который изменился в обеих раскладках. Порядок:

1. **Документация** (`docs/`, `memory/`) — сравнивать по смыслу: у кого правка новее и ближе к реальности.
   Обе правки полезны — слить вручную в `.claude`, затем `export --force`.
2. **Агенты и скиллы** — `.claude` считается источником, если у DeepSeek нет отдельной причины (например,
   новый агент, которого в `.claude` нет). Новый агент переносится `import` и получает `.claude`-формат.
3. **Служебные** (`hooks.json`, `session_state.json`) — доверять дате файла; обычно побеждает Claude Code.
4. Любой конфликт, который нельзя решить без домысла, — вопрос пользователю (правило проекта).

## Постоянная работа в DeepSeek

Если Claude Code не вернётся:

1. Объявить `.deepseek` основной раскладкой: в `README.md` убрать «временная», `CLAUDE.md` переименовать
   (если получится) в исторический источник, `.claude` перестать обновлять.
2. Прогнать `export` последний раз и зафиксировать снимок коммитом — дальше `.deepseek` живёт сам.
3. Каталоги `.claude` не удалять: там история, инструменты и то, что не конвертируется (`exports`,
   `worktrees`).
4. Скрипты `convert.py`/`selftest.py` оставить: они проверяют целостность (симметрию копий, отсутствие
   ссылок на `.claude` в `.deepseek`-документах).
5. Ветки `-deepseek` и `MIGRATION.md` — в архив: возврата в Claude Code больше не планируется.

## Когда правило проекта меняется {#правило проекта}

Порядок, чтобы не разошлись три копии (`CLAUDE.md`, `AGENTS.md`, `instructions/`):

1. Claude Code доступен: правка в `CLAUDE.md` -> `export` (обновит `AGENTS.md` и `instructions/project.md`
   сам). Файл `instructions/rules.md` не дублирует `CLAUDE.md`, а дополняет; правило, общее для обоих
   движков, живёт в `CLAUDE.md`, специфика DeepSeek — в `instructions/rules.md`.
2. Claude Code недоступен: правка в `instructions/rules.md` (общее) — при возврате её текст переносится
   в `CLAUDE.md` вручную или через `import` как документ, после чего `export` выравнивает остальное.
