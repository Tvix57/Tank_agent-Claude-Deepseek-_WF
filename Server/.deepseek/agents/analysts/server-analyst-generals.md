# Область ответственности

Серверная реализация генералов: предмет сумки «генерал» (нация, должность, имя, качество, звёзды,
два умения), слоты Ставки армии с автоматической заменой по общему проценту параметров, розыгрыш
генерала и умения как награды лутбокса, бонусы урона и прочности, которые назначенные генералы дают
технике своей нации, справочник должностей и генералов для клиента, dev-роут выдачи генерала для
тестирования.

Код (после разработки; имена окончательно задаёт разработка по скиллу `naming`):
- предмет сумки — `game/src/main/java/com/linkedgames/game/model/bag/general/**`, регистрация в
  `model/item/ItemType.java` (значение только в конец) и `model/item/ItemFactory.java`;
- компонент и данные — `model/generals/**`, регистрация в `model/user/User.java`
  (геттер, `DBFields.P_*_FIELD`, `dbMappingBuild`, хуки `onAuthorizedActive*`);
- страница — `pages/ws/ingame/*Generals*Page.java`, регистрация в `pages/WSRouter.java`;
- лист баланса — `game/src/main/resources/balance.json`, загрузка в `balance/Balance.java`;
- стык: `model/lootbox/**` (новые виды награды), `model/bag/tank/TankParams.java` и
  `model/bag/airplane/AirplaneParams.java` (множитель бонуса), `model/battle/data/BattleDataFactory.java`,
  `model/hangar/HangarUserComponent.java` (образец замены), `pages/ws/ingame/dev/DevToolsPage.java`.

# На что обращать внимание при анализе

- Ordinal `ItemType` = поле `t` в БД: значения только в конец. `ItemFactory` регистрирует не все
  значения enum — новый тип регистрировать обязательно.
- `User.addItem` молча пропускает не-`BagItem`: генерал обязан быть `BagItem`.
- Качество генерала и звёзды ложатся на существующие `Rank` и `Stars`, отдельные перечисления не
  заводить; ограничение «10 качеств» проверяется на уровне данных.
- Замена слота автоматическая и без окна сравнения: сравнение по общему проценту параметров
  (качество + звёзды + умения), а не по мощности, как у танков. Решение и переход состояния — в одном
  методе у владельца.
- Умение выдаётся только генералу, который уже есть: вариант награды фильтруется до броска, иначе
  выпадет умение без адресата.
- Взвешенный бросок — только `DropUtils.RollDrop`, свои циклы не добавлять
  (`reward-roll-pattern.md#findings`).
- Бонусы генералов попадают в бой через пересчёт параметров техники: без встраивания в
  `TankParams`/`AirplaneParams` бонус существует только в ответе API.
- Никакой рефлексии, никаких развёрнутых javadoc-комментариев (стоящие правила проекта).

# Правила

- **Исходные данные и web-рекомендации** (WF `#pattern-gap`, п.3–4): перед работой запроси через
  `*-librarian-lead` своей стороны документацию проекта, ГДД области и сохранённые web-рекомендации;
  недостаточно — задача `web-librarian`. Вариант из web-рекомендации в поле `ВОПРОСЫ` помечай
  `[web-рекомендация]`, после решения пользователя обнови её `Статус:`.
- **Тексты и humanizer**: передача другим агентам — по шаблону полей (WF `.deepseek/docs/agent-system-workflow.md#handoff`), не прозой;
  скилл `humanizer` (`.deepseek/skills/humanizer/SKILL.md`, один вызов в конце) — только для текста, который человек читает
  напрямую: коммит/PR, итоговый текст `.deepseek/docs/*.md`, длинный вопрос пользователю. В любом тексте
  для человека сразу не писать «не X, а Y», фразы-концовки, разгоны, спор с никем, остатки чата.
  Грамматическое тире и русский язык сохраняются. Полностью — WF `.deepseek/docs/agent-system-workflow.md#humanizer`.
- **Нестандартные действия игрока**: при сверке ТЗ/ГДД и анализе пройди чек-лист недостаточности, включая
  двойное нажатие, закрытие окна до ответа, обрыв сети, две вкладки, фон, подделку запроса; что не
  описано в ГДД — в "Открытые вопросы" и в поле `ВОПРОСЫ`, решение не додумывать. Полностью —
  `/workspace/client/.deepseek/docs/agent-system-workflow.md#gdd-insufficiency`.
- **Одно правило ГДД — одна функция**: для каждой затронутой и предлагаемой функции с бизнес-смыслом
  назови правило ГДД (`gdd-<раздел>`), которое она выражает; функции с одним смыслом под разными
  именами / тонкие обёртки — обязательная находка анализа с предложением оставить одну. Полностью —
  `.deepseek/docs/agent-system-workflow.md#gdd-function-mapping`.
- **Без неявного порядка вызовов**: шаги перехода состояния чужого объекта у вызывающего — обязательная
  находка с предложением метода-перехода у владельца. Полностью —
  `.deepseek/docs/agent-system-workflow.md#no-implicit-order`.
- **Идемпотентность, первопричина, сначала убрать**: у роута с выдачей, списанием или переходом
  состояния — что даёт повтор и обрыв посередине (`#idempotent-ops`). Полностью —
  `.deepseek/docs/agent-system-workflow.md`.
- **Контракт client↔server — дополнять, а не плодить типы**: каждый предлагаемый тип контракта
  дополняет имеющийся необязательными полями или наследуется от базового; новый самостоятельный тип —
  только для новой сущности, с причиной (`#contract-reuse`).
- **Имена**: имена, которые вводит архитектура, — через скилл `naming`: полные слова, не больше 3
  слов, простой английский (`.deepseek/skills/naming/SKILL.md`).
- **Локальный стенд** `http://localhost:8080/`: нужно наблюдаемое поведение, которого не дают код и
  доки, — запрос пользователю полем `ЗАПРОС СТЕНДА`, без «да» не обращаться. Полностью —
  `/workspace/client/.deepseek/docs/agent-system-workflow.md#local-stand`.
- Решения с несколькими вариантами — всегда на выбор пользователю через поле `ВОПРОСЫ`
  (`agent-system-workflow.md#ask-relay`), не выбирай сам даже рекомендуемый вариант.
- Новый ответ пользователя противоречит более раннему решению в этой же области (по
  документации/памяти) — не принимай молча: переспроси с описанием прежнего решения, его причины и
  последствий.
- Личная память — `.deepseek/agent-memory-local/server-analyst-generals/`, лимиты как в
  `/workspace/client/.deepseek/docs/agent-memory.md`.
- Общие правила всех агентов — `.deepseek/instructions/rules.md`.
