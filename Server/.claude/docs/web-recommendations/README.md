# Web-рекомендации (server) — индекс и регламент

Сохранённые результаты поиска `web-librarian` во внешних источниках для задач сервера. Клиентские
рекомендации хранятся отдельно, в `/workspace/client/.claude/docs/web-recommendations/`.
Web-рекомендация — внешний совет, а не конвенция проекта. Принятой в проекте она становится только
по решению пользователя (поле `Статус`).

**Содержание:** [Индекс тем](#index) · [Структура файла темы](#topic-structure) ·
[Точечный поиск](#search) · [Точечная запись](#write)

## Индекс тем {#index}

Одна строка на файл темы: `` `<тема>.md` — <ключевые слова через запятую> ``. Ключевые слова — те
слова, по которым тему будут искать (технология, задача, понятие), латиницей и по-русски.

`idempotent-reward-grant.md` — idempotency key, идемпотентность, выдача награды, лутбокс, сундук, двойное нажатие, retry, unique index, E11000, MongoDB, outbox, журнал выдачи

## Структура файла темы {#topic-structure}

Файл `<тема>.md` (kebab-case, латиница, например `mongo-bulk-write.md`) — все рекомендации по
одной теме. Одна рекомендация — один раздел `##` с якорем `{#web-<slug>}`; поля раздела всегда одни
и те же и идут в этом порядке:

```markdown
## <Короткое название рекомендации> {#web-<slug>}

- **Задача:** какую проблему проекта решали (1 строка).
- **Ключевые слова:** <те же, что в индексе, плюс уточняющие>.
- **Рекомендация:** суть, 2–5 строк.
- **Плюсы:** пункты.
- **Минусы:** пункты, включая несовместимость с конвенциями проекта.
- **Применимость к проекту:** версии (Java, MongoDB-драйвер), конфликт с правилами `CLAUDE.md`, если есть.
- **Источники:** URL — дата обращения (YYYY-MM-DD).
- **Статус:** не применялось | принято (YYYY-MM-DD, где применено) | отклонено (YYYY-MM-DD, причина).
```

В начале файла — строка `# <Тема>` и оглавление из ссылок на якоря `{#web-<slug>}`.

## Точечный поиск {#search}

Шаги ниже выполняет любой агент, которому нужны сохранённые рекомендации (библиотекари, аналитики,
`web-librarian` перед новым поиском). Файл темы целиком не читать.

1. `grep -n -i '<слово1>\|<слово2>' README.md` по разделу [индекса](#index) — выбрать файлы тем.
   Совпадений нет — рекомендаций нет, поиск закончен.
2. `grep -n -i '^## \|Ключевые слова' <тема>.md` — выбрать разделы `{#web-<slug>}` по совпадению
   ключевых слов.
3. `sed -n 'A,Bp' <тема>.md` — прочитать только выбранные разделы (от их `##` до следующего `##`).

Готово, когда для запроса названы конкретные `<тема>.md#web-<slug>` с их статусом, либо установлено,
что подходящих разделов нет.

## Точечная запись {#write}

Записывает только `web-librarian` (новые разделы), статус меняет аналитик после решения
пользователя. Запись — только `Edit`; `Write` — только для нового файла темы.

1. Перед записью — [точечный поиск](#search): похожий раздел есть — дополнить его поля, не заводить
   дубль.
2. Тема есть — добавить раздел в конец её файла и ссылку в её оглавление.
3. Темы нет — создать `<тема>.md` по [структуре](#topic-structure) и добавить строку в
   [индекс](#index).
4. Смена статуса — `Edit` одной строки `Статус:` в нужном разделе.

Готово, когда раздел есть в файле темы, ссылка — в оглавлении темы, строка темы — в индексе.
